# Enagram.io v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Enagram.io v2: the same app, features and look as v1, with the gbrain/Render/Colab storage layer replaced by Supabase Postgres + pgvector searched directly from Vercel, so the whole thing runs on Vercel + Supabase with nothing to start by hand.

**Architecture:** A new `src/lib/store/` layer owns all database access behind a small `Db` interface (production: `postgres` driver; tests: in-process PGlite with pgvector). Search is hybrid (Gemini embedding + Postgres full-text) merged with Reciprocal Rank Fusion. Sync runs inside a Vercel route in two idempotent phases (fetch, then chunked embed). Everything else (UI, Google login, Google clients, chat tools and prompt) carries over from v1.

**Tech Stack:** Next.js 16 (App Router), TypeScript, Vercel AI SDK + Gemini, NextAuth v5, `postgres` (porsager) driver, Supabase Postgres + pgvector, PGlite (tests), `node:test`.

**Spec:** `docs/superpowers/specs/2026-10-07-enagram-v2-design.md` (read it first; this plan implements it).

## Global Constraints

Every task's requirements implicitly include all of these.

- Runtime services: **Vercel + Supabase** only (plus Google APIs and Gemini). No Render, Colab, ngrok or gbrain anywhere in v2 code.
- Read `node_modules/next/dist/docs/` before writing any Next.js code (the repo's `AGENTS.md` requires it; this Next version differs from older ones).
- All tables are prefixed `enagram_`. Embeddings: Gemini `gemini-embedding-001`, `outputDimensionality` 768, column `vector(768)`. Embed text is `title + first 6000 characters of body`; the full body stays keyword-searchable.
- Search: keyword side = alphanumeric terms (max 12) OR-ed into `to_tsquery('english', 't1 | t2 | ...')`, 30 candidates; vector side = cosine distance, 30 candidates; merge with Reciprocal Rank Fusion, k = 60.
- Sync: `fetch` phase then `embed` phase (about 40s time budget per request). Gmail: 100 most recent, excluding Promotions/Social. Auto-sync on page load is skipped when the last sync was under 10 minutes ago.
- Chat tool names, input schemas, descriptions (except the one find_related wording fix in Task 9), the system prompt, the model id and the 28s tool budget are unchanged from v1.
- Dependency versions are exact (no `^` or `~`). `.nvmrc` contains `24`. Do **not** add an `engines` field to `package.json`.
- Modules covered by `node:test` use **relative imports with explicit `.ts` extensions**, never the `@/` alias, and must not import `next/*` or `googleapis` (node cannot resolve those). `import type` is fine (it is erased).
- Every SQL parameter is explicitly cast (`$1::text[]`, `$1::jsonb`, `$1::vector`, `$1::timestamptz`) because production runs the driver with `prepare: false`.
- Git: every commit is authored by the user only. **Never** add `Co-Authored-By`, "Generated with Claude Code" or any attribution line to a commit message, PR or file. Before every push run: `git log origin/main..HEAD --format=%B | grep -i -E "co-authored|claude|generated with" || echo "no attribution lines"` and require `no attribution lines`.
- Before saying any task is done, run its verification commands and read the output (superpowers:verification-before-completion).

- [ ] **Step 3: Create `src/lib/store/schema.ts`**

```ts
import type { Db } from "./db.ts";

export const EMBEDDING_DIMENSIONS = 768;

/**
 * Idempotent, run once per cold start (service.ts). Table names are prefixed
 * `enagram_` so they cannot collide with gbrain's tables in the same Supabase
 * project. Two cold starts racing `create table if not exists` can make one of
 * them fail; the failure is not cached, so the next request succeeds.
 *
 * `fts` turns `_ . / -` into spaces before tokenising: otherwise a file named
 * `Resume_2026_APRIL.pdf` is one token that a search for "resume" misses.
 */
export const SCHEMA_STATEMENTS: string[] = [
  `create extension if not exists vector`,
  `create table if not exists enagram_documents (
     id           text primary key,
     source       text not null check (source in ('gmail', 'drive', 'calendar')),
     title        text not null,
     body         text not null,
     url          text,
     doc_date     timestamptz,
     participants text[] not null default '{}',
     event_id     text,
     content_hash text not null,
     embedding    vector(${EMBEDDING_DIMENSIONS}),
     fts          tsvector generated always as (
                    to_tsvector('english',
                      regexp_replace(coalesce(title, '') || ' ' || coalesce(body, ''), '[_./-]+', ' ', 'g'))
                  ) stored,
     updated_at   timestamptz not null default now()
   )`,
  `create index if not exists enagram_documents_fts on enagram_documents using gin (fts)`,
  `create index if not exists enagram_documents_participants on enagram_documents using gin (participants)`,
  `create table if not exists enagram_links (
     from_id text not null references enagram_documents(id) on delete cascade,
     to_id   text not null references enagram_documents(id) on delete cascade,
     primary key (from_id, to_id)
   )`,
  `create table if not exists enagram_preferences (
     id         bigserial primary key,
     fact       text not null,
     created_at timestamptz not null default now()
   )`,
  `create table if not exists enagram_meta (key text primary key, value text not null)`,
];

export async function applySchema(db: Db): Promise<void> {
  for (const statement of SCHEMA_STATEMENTS) {
    await db.query(statement);
  }
}
```

```ts
export function toIso(value: Date | string | null | undefined): string | undefined {
  if (!value) return undefined;
  const date = value instanceof Date ? value : new Date(value);
  return Number.isNaN(date.getTime()) ? undefined : date.toISOString();
}
```

```ts
import { PGlite } from "@electric-sql/pglite";
import { vector } from "@electric-sql/pglite-pgvector";
import type { Db, Row } from "./db.ts";
import { EMBEDDING_DIMENSIONS } from "./schema.ts";
import type { StoredDocument } from "./types.ts";

type Queryable = { query: PGlite["query"] };

function wrapTransaction(tx: Queryable): Db {
  const self: Db = {
    query: async <T extends Row = Row>(text: string, params: unknown[] = []) =>
      (await tx.query<T>(text, params)).rows,
    transaction: async <T>(fn: (inner: Db) => Promise<T>) => fn(self),
  };
  return self;
}

/** A fresh, isolated, in-memory Postgres with pgvector. Tests only. */
export async function createTestDb(): Promise<Db> {
  const pg = new PGlite({ extensions: { vector } });
  await pg.exec("create extension if not exists vector;");
  return {
    query: async <T extends Row = Row>(text: string, params: unknown[] = []) =>
      (await pg.query<T>(text, params)).rows,
    transaction: async <T>(fn: (tx: Db) => Promise<T>) => pg.transaction((tx) => fn(wrapTransaction(tx))),
  };
}

export function unitVector(index: number): number[] {
  const values = new Array<number>(EMBEDDING_DIMENSIONS).fill(0);
  values[index] = 1;
  return values;
}

export function makeDoc(overrides: Partial<StoredDocument> & { id: string }): StoredDocument {
  return {
    source: "gmail",
    title: "Title",
    body: "Body",
    url: null,
    docDate: null,
    participants: [],
    eventId: null,
    ...overrides,
  };
}

export async function setVector(db: Db, id: string, index: number): Promise<void> {
  await db.query(`update enagram_documents set embedding = $2::vector where id = $1`, [
    id,
    `[${unitVector(index).join(",")}]`,

}
```

```ts
import postgres from "postgres";
import type { Db, Row } from "./db.ts";

const QUERY_TIMEOUT_MS = 15_000;

/**
 * A dead or paused database must produce an error in seconds, not hold a
 * Vercel function until its 60s kill. JS-level race rather than a Postgres
 * `statement_timeout` startup parameter, which Supabase's pooler may reject.
 */
function withTimeout<T>(promise: Promise<T>, ms: number): Promise<T> {
  let timer: ReturnType<typeof setTimeout> | undefined;
  const timeout = new Promise<never>((_, reject) => {
    timer = setTimeout(() => reject(new Error(`database did not respond within ${Math.round(ms / 1000)}s`)), ms);
  });
  return Promise.race([promise, timeout]).finally(() => clearTimeout(timer));
}

function wrap(sql: postgres.Sql, inTransaction: boolean): Db {
  const self: Db = {
    query: async <T extends Row = Row>(text: string, params: unknown[] = []) =>
      withTimeout(sql.unsafe(text, params as never[]) as unknown as Promise<T[]>, QUERY_TIMEOUT_MS),
    transaction: async <T>(fn: (tx: Db) => Promise<T>) => {
      if (inTransaction) return fn(self);
      return (await sql.begin((tx) => fn(wrap(tx as unknown as postgres.Sql, true)))) as unknown as T;
    },
  };
  return self;
}

/**
 * `prepare: false` and `ssl: "require"` are what Supabase's transaction-mode
 * pooler (port 6543) needs. One connection per serverless instance is plenty.
 */
export function createPostgresDb(url: string): Db {
  const sql = postgres(url, { prepare: false, ssl: "require", max: 1, idle_timeout: 20, connect_timeout: 15 });
  return wrap(sql, false);
}
```

```ts
import { createHash } from "node:crypto";
import type { Db } from "./db.ts";
import type { StoredDocument } from "./types.ts";

export const EMBED_TEXT_CHARS = 6000;
const UPSERT_BATCH_SIZE = 25;

/** Postgres text cannot hold NUL bytes, and PDF extraction can emit them. */
function clean(value: string): string {
  return value.replace(/\u0000/g, "");
}

export function contentHash(doc: StoredDocument): string {
  return createHash("sha256")
    .update(JSON.stringify([doc.title, doc.body, doc.url, doc.docDate, doc.participants]))
    .digest("hex");
}

export function embeddingText(title: string, body: string): string {
  return `${title}\n\n${body.slice(0, EMBED_TEXT_CHARS)}`;
}

// One statement per batch (not per row): 100+ documents one round-trip at a
// time would cost many seconds against a remote database.
const UPSERT_SQL = `
  insert into enagram_documents
    (id, source, title, body, url, doc_date, participants, event_id, content_hash)
  select id, source, title, body, url, doc_date, coalesce(participants, '{}'), event_id, content_hash
    from jsonb_to_recordset($1::jsonb) as r(
      id text, source text, title text, body text, url text, doc_date timestamptz,
      participants text[], event_id text, content_hash text)
  on conflict (id) do update set
    source = excluded.source, title = excluded.title, body = excluded.body, url = excluded.url,
    doc_date = excluded.doc_date, participants = excluded.participants, event_id = excluded.event_id,
    content_hash = excluded.content_hash, embedding = null, updated_at = now()`;

export async function upsertDocuments(
  db: Db,
  docs: StoredDocument[],
): Promise<{ total: number; changed: number }> {
  if (docs.length === 0) return { total: 0, changed: 0 };

  const cleaned = docs.map((d) => ({ ...d, title: clean(d.title), body: clean(d.body) }));
  const withHash = cleaned.map((doc) => ({ doc, hash: contentHash(doc) }));

  const existing = await db.query<{ id: string; content_hash: string }>(
    `select id, content_hash from enagram_documents where id = any($1::text[])`,
    [cleaned.map((d) => d.id)],
  );
  const known = new Map(existing.map((r) => [r.id, r.content_hash]));
  const changed = withHash.filter(({ doc, hash }) => known.get(doc.id) !== hash);

  for (let i = 0; i < changed.length; i += UPSERT_BATCH_SIZE) {
    const payload = changed.slice(i, i + UPSERT_BATCH_SIZE).map(({ doc, hash }) => ({
      id: doc.id,
      source: doc.source,
      title: doc.title,
      body: doc.body,
      url: doc.url,
      doc_date: doc.docDate,
      participants: doc.participants,
      event_id: doc.eventId,
      content_hash: hash,
    }));
    await db.query(UPSERT_SQL, [JSON.stringify(payload)]);
  }

  return { total: docs.length, changed: changed.length };
}

/** The calendar fetch is a full window, so anything in it that vanished was deleted in Google. */
export async function deleteCalendarExcept(db: Db, keepIds: string[]): Promise<number> {
  const rows = await db.query<{ id: string }>(
    `delete from enagram_documents where source = 'calendar' and not (id = any($1::text[])) returning id`,
    [keepIds],
  );
  return rows.length;
}

export type PendingEmbedding = { id: string; hash: string; text: string };

export async function pendingEmbeddings(db: Db, limit: number): Promise<PendingEmbedding[]> {
  const rows = await db.query<{ id: string; content_hash: string; title: string; body: string }>(
    `select id, content_hash, title, left(body, $2::int) as body
       from enagram_documents where embedding is null
      order by updated_at desc, id limit $1::int`,
    [limit, EMBED_TEXT_CHARS],
  );
  return rows.map((r) => ({ id: r.id, hash: r.content_hash, text: embeddingText(r.title, r.body) }));
}

/** Only writes when the row still has the hash the embedding was computed from. */
export async function setEmbeddings(
  db: Db,
  items: { id: string; hash: string; embedding: number[] }[],
): Promise<void> {
  if (items.length === 0) return;
  const payload = items.map((i) => ({ id: i.id, hash: i.hash, embedding: `[${i.embedding.join(",")}]` }));
  await db.query(
    `update enagram_documents d set embedding = r.embedding::vector
       from jsonb_to_recordset($1::jsonb) as r(id text, hash text, embedding text)
      where d.id = r.id and d.content_hash = r.hash`,
    [JSON.stringify(payload)],
  );
}

export async function countPending(db: Db): Promise<number> {
  const [row] = await db.query<{ n: number }>(
    `select count(*)::int as n from enagram_documents where embedding is null`,
  );
  return row.n;
}

export async function countDocuments(db: Db): Promise<number> {
  const [row] = await db.query<{ n: number }>(`select count(*)::int as n from enagram_documents`);
  return row.n;
}
```

```ts
import type { Db } from "./db.ts";
import { toIso } from "./format.ts";
import { HIT_TYPE_BY_SOURCE, type BrainSearchHit, type SourceKind } from "./types.ts";

const CANDIDATES = 30;
const MAX_TERMS = 12;
const RRF_K = 60;

/** Reciprocal Rank Fusion: an id's score is the sum of 1/(k + rank) across the lists it appears in. */
export function rrfFuse(lists: string[][], k = RRF_K): { id: string; score: number }[] {
  const scores = new Map<string, number>();
  for (const list of lists) {
    list.forEach((id, rank) => scores.set(id, (scores.get(id) ?? 0) + 1 / (k + rank + 1)));
  }
  return Array.from(scores, ([id, score]) => ({ id, score })).sort((a, b) => b.score - a.score);
}

/**
 * OR, not AND: Postgres's websearch_to_tsquery ANDs every word, so a full
 * sentence like "Update me for the TCS mail which came?" matched zero documents
 * (verified 2026-10-07). With OR and the english config (which drops stop words),
 * documents matching more of the rare terms rank higher. Built with `new RegExp`
 * because this project's TS target (ES2017) rejects \p{...} regex literals.
 */
export function buildTsQuery(question: string): string | null {
  const terms = Array.from(new Set(question.toLowerCase().match(new RegExp("[\\p{L}\\p{N}]+", "gu")) ?? [])).slice(
    0,
    MAX_TERMS,
  );
  return terms.length > 0 ? terms.join(" | ") : null;
}

export function vectorLiteral(values: number[]): string {
  return `[${values.join(",")}]`;
}

export type SearchOptions = {
  query: string;
  queryEmbedding?: number[] | null;
  source?: SourceKind;
  limit?: number;
};

type HitRow = {
  id: string;
  source: SourceKind;
  title: string;
  url: string | null;
  doc_date: Date | string | null;
  event_id: string | null;
  body: string;
  headline: string | null;
};

function snippetOf(row: HitRow): string {
  const text = (row.headline || row.body).replace(/<\/?b>/g, "").replace(/\s+/g, " ").trim();
  return text.slice(0, 600);
}

export async function searchDocuments(db: Db, options: SearchOptions): Promise<BrainSearchHit[]> {
  const { query, queryEmbedding = null, source = null, limit = 10 } = options;
  const tsQuery = buildTsQuery(query);

  const keywordRows = tsQuery
    ? await db.query<{ id: string }>(
        `select id from enagram_documents, to_tsquery('english', $1::text) q
          where fts @@ q and ($2::text is null or source = $2::text)
          order by ts_rank_cd(fts, q) desc, doc_date desc nulls last
          limit ${CANDIDATES}`,
        [tsQuery, source],
      )
    : [];

  const vectorRows = queryEmbedding
    ? await db.query<{ id: string }>(
        `select id from enagram_documents
          where embedding is not null and ($2::text is null or source = $2::text)
          order by embedding <=> $1::vector
          limit ${CANDIDATES}`,
        [vectorLiteral(queryEmbedding), source],
      )
    : [];

  const fused = rrfFuse([keywordRows.map((r) => r.id), vectorRows.map((r) => r.id)]).slice(0, limit);
  if (fused.length === 0) return [];

  const rows = await db.query<HitRow>(
    `select id, source, title, url, doc_date, event_id, left(body, 2000) as body,
            case when $2::text is null then null
                 else ts_headline('english', left(body, 20000), to_tsquery('english', $2::text),
                                  'MaxWords=60, MinWords=25, MaxFragments=1')
            end as headline
       from enagram_documents where id = any($1::text[])`,
    [fused.map((f) => f.id), tsQuery],
  );
  const byId = new Map(rows.map((r) => [r.id, r]));

  return fused.flatMap(({ id, score }) => {
    const row = byId.get(id);
    if (!row) return [];
    return [
      {
        slug: row.id,
        type: HIT_TYPE_BY_SOURCE[row.source],
        title: row.title,
        score: Math.round(score * 10_000) / 10_000,
        snippet: snippetOf(row),
        url: row.url ?? undefined,
        date: toIso(row.doc_date),
        eventId: row.event_id ?? undefined,
      },
    ];
  });
}
```

```ts
import type { Db } from "./db.ts";
import { toIso } from "./format.ts";
import { HIT_TYPE_BY_SOURCE, type BrainSearchHit, type SourceKind } from "./types.ts";

export type LinkCandidate = { id: string; source: SourceKind; participants: string[] };
export type LinkPair = { from: string; to: string };

const MAX_DOCS_PER_PARTICIPANT = 6; // mailing lists / frequent contacts are not a meaningful signal
const MAX_LINKS = 200;

/**
 * Deterministic cross-source linking (no LLM judgment): a Gmail thread, a Drive
 * file and a Calendar event that share a participant are almost certainly the
 * same real-world thread. Same rules as v1.
 */
export function buildLinkPairs(docs: LinkCandidate[], ownEmail: string): LinkPair[] {
  const own = ownEmail.trim().toLowerCase();
  const byParticipant = new Map<string, LinkCandidate[]>();
  for (const doc of docs) {
    for (const raw of doc.participants) {
      const participant = raw.trim().toLowerCase();
      if (!participant || participant === own) continue; // the user is on nearly everything
      const list = byParticipant.get(participant) ?? [];
      if (!list.some((d) => d.id === doc.id)) list.push(doc);
      byParticipant.set(participant, list);
    }
  }

  const seen = new Set<string>();
  const pairs: LinkPair[] = [];
  for (const entries of byParticipant.values()) {
    if (entries.length < 2 || entries.length > MAX_DOCS_PER_PARTICIPANT) continue;
    for (let i = 0; i < entries.length; i++) {
      for (let j = i + 1; j < entries.length; j++) {
        if (entries[i].source === entries[j].source) continue; // cross-source only
        const key = [entries[i].id, entries[j].id].sort().join("|");
        if (seen.has(key)) continue;
        seen.add(key);
        pairs.push({ from: entries[i].id, to: entries[j].id });
      }
    }
  }
  return pairs.slice(0, MAX_LINKS);
}

export async function replaceLinks(db: Db, pairs: LinkPair[]): Promise<void> {
  await db.transaction(async (tx) => {
    await tx.query(`delete from enagram_links`);
    if (pairs.length === 0) return;
    await tx.query(
      `insert into enagram_links (from_id, to_id)
       select from_id, to_id from jsonb_to_recordset($1::jsonb) as r(from_id text, to_id text)
       on conflict do nothing`,
      [JSON.stringify(pairs.map((p) => ({ from_id: p.from, to_id: p.to })))],
    );
  });
}

export async function rebuildLinks(db: Db, ownEmail: string): Promise<number> {
  const rows = await db.query<{ id: string; source: SourceKind; participants: string[] }>(
    `select id, source, participants from enagram_documents where cardinality(participants) > 0`,
  );
  const pairs = buildLinkPairs(rows, ownEmail);
  await replaceLinks(db, pairs);
  return pairs.length;
}

export type RelatedPage = {
  slug: string;
  title: string;
  type: BrainSearchHit["type"];
  url?: string;
  date?: string;
};

export async function relatedTo(db: Db, id: string): Promise<{ count: number; results: RelatedPage[] }> {
  const rows = await db.query<{
    id: string;
    title: string;
    source: SourceKind;
    url: string | null;
    doc_date: Date | string | null;
  }>(
    `select d.id, d.title, d.source, d.url, d.doc_date
       from enagram_links l
       join enagram_documents d on d.id = case when l.from_id = $1::text then l.to_id else l.from_id end
      where l.from_id = $1::text or l.to_id = $1::text
      limit 10`,
    [id],
  );
  const results = rows.map((r) => ({
    slug: r.id,
    title: r.title,
    type: HIT_TYPE_BY_SOURCE[r.source],
    url: r.url ?? undefined,
    date: toIso(r.doc_date),
  }));
  return { count: results.length, results };
}
```

```ts
export async function addPreference(db: Db, fact: string): Promise<{ status: "saved" | "already_known" }> {
  const trimmed = fact.trim();
  const known = await db.query<{ id: number }>(
    `select id from enagram_preferences where position(lower($1::text) in lower(fact)) > 0 limit 1`,
    [trimmed],

  await db.query(`insert into enagram_preferences (fact) values ($1::text)`, [trimmed]);
  await db.query(
    `delete from enagram_preferences
      where id not in (select id from enagram_preferences order by id desc limit ${MAX_PREFERENCES})`,
```

```ts
import { embed, embedMany, type EmbeddingModel } from "ai";
import { google, type GoogleEmbeddingModelOptions } from "@ai-sdk/google";
import { EMBEDDING_DIMENSIONS } from "./store/schema.ts";

export type Embedder = {
  documents(texts: string[]): Promise<number[][]>;
  query(text: string): Promise<number[]>;
};

function options(taskType: "RETRIEVAL_DOCUMENT" | "RETRIEVAL_QUERY") {
  return { google: { outputDimensionality: EMBEDDING_DIMENSIONS, taskType } satisfies GoogleEmbeddingModelOptions };
}

/**
 * Same model and size v1's gbrain used (gemini-embedding-001 at 768 dimensions).
 * Reads GOOGLE_GENERATIVE_AI_API_KEY at call time, not at import.
 */
export function createEmbedder(model: EmbeddingModel = google.embedding("gemini-embedding-001")): Embedder {
  return {
    async documents(texts) {
      if (texts.length === 0) return [];
      const { embeddings } = await embedMany({
        model,
        values: texts,
        providerOptions: options("RETRIEVAL_DOCUMENT"),
        maxRetries: 2,
      });
      return embeddings;
    },
    async query(text) {
      const { embedding } = await embed({
        model,
        value: text,
        providerOptions: options("RETRIEVAL_QUERY"),
        maxRetries: 1,
      });
      return embedding;
    },
  };
}
```

```ts
import type { BrainDocument } from "../brain/types.ts";
import type { Db } from "../store/db.ts";
import {
  countDocuments,
  countPending,
  deleteCalendarExcept,
  pendingEmbeddings,
  setEmbeddings,
  upsertDocuments,
} from "../store/documents.ts";
import { rebuildLinks } from "../store/links.ts";
import { setMeta } from "../store/meta.ts";
import { toStoredDocument } from "./to-stored.ts";

export type FetchedDocuments = { gmail: BrainDocument[]; drive: BrainDocument[]; calendar: BrainDocument[] };

export type SyncDeps = {
  db: Db;
  fetchDocuments: () => Promise<FetchedDocuments>;
  embedDocuments: (texts: string[]) => Promise<number[][]>;
  ownEmail: string;
  /** Calendar-only re-ingests pass false so they don't postpone the next full auto-sync. */
  touchLastSynced?: boolean;
  now?: () => number;
};

export type SyncProgress = {
  phase: "fetch" | "embed";
  skipped?: boolean;
  counts: { gmail: number; drive: number; calendar: number } | null;
  documents: number;
  changed: number;
  embedded: number;
  remaining: number;
};

/** Leaves ~20s of Vercel's 60s limit for the request itself and the response. */
export const EMBED_BUDGET_MS = 40_000;
const EMBED_BATCH_SIZE = 20;

/**
 * Phase 1: pull from Google, store text, and relink. Cheap and idempotent:
 * unchanged documents are not rewritten and keep their embeddings.
 */
export async function runFetchPhase(deps: SyncDeps): Promise<SyncProgress> {
  const fetched = await deps.fetchDocuments();
  const all = [...fetched.gmail, ...fetched.drive, ...fetched.calendar].map(toStoredDocument);

  const { changed } = await upsertDocuments(deps.db, all);
  // The calendar fetch is a complete window, so anything missing from it was deleted in Google.
  const removed = await deleteCalendarExcept(
    deps.db,
    fetched.calendar.map((d) => d.id),
  );
  if (changed > 0 || removed > 0) await rebuildLinks(deps.db, deps.ownEmail);
  if (deps.touchLastSynced !== false) {
    await setMeta(deps.db, "last_synced_at", String((deps.now ?? Date.now)()));
  }

  return {
    phase: "fetch",
    counts: { gmail: fetched.gmail.length, drive: fetched.drive.length, calendar: fetched.calendar.length },
    documents: await countDocuments(deps.db),
    changed,
    embedded: 0,
    remaining: await countPending(deps.db),
  };
}

/**
 * Phase 2: embed pending documents until the time budget is spent. Failures
 * (e.g. free-tier rate limits) are logged and leave rows pending; keyword
 * search works on them meanwhile, so a failed embedding never hides data.
 */
export async function runEmbedPhase(
  deps: SyncDeps,
  budgetMs = EMBED_BUDGET_MS,
  batchSize = EMBED_BATCH_SIZE,
): Promise<SyncProgress> {
  const now = deps.now ?? Date.now;
  const start = now();
  let embedded = 0;

  while (now() - start < budgetMs) {
    const batch = await pendingEmbeddings(deps.db, batchSize);
    if (batch.length === 0) break;

    let vectors: number[][];
    try {
      vectors = await deps.embedDocuments(batch.map((b) => b.text));
    } catch (err) {
      console.error("Embedding batch failed; documents stay pending", err);
      break;
    }
    if (vectors.length !== batch.length) {
      console.error(`Embedder returned ${vectors.length} vectors for ${batch.length} documents; stopping`);
      break;
    }

    await setEmbeddings(
      deps.db,
      batch.map((b, i) => ({ id: b.id, hash: b.hash, embedding: vectors[i] })),
    );
    embedded += batch.length;
  }

  return {
    phase: "embed",
    counts: null,
    documents: await countDocuments(deps.db),
    changed: 0,
    embedded,
    remaining: await countPending(deps.db),
  };
}
```

```ts
import type { Embedder } from "../embeddings.ts";
import type { Db } from "./db.ts";
import { relatedTo, type RelatedPage } from "./links.ts";
import { addPreference, listPreferences, removePreference } from "./preferences.ts";
import { searchDocuments } from "./search.ts";
import type { BrainSearchHit, SourceKind } from "./types.ts";

export type Brain = {
  searchGmail(query: string, limit?: number): Promise<BrainSearchHit[]>;
  searchDrive(query: string, limit?: number): Promise<BrainSearchHit[]>;
  searchCalendar(query: string, limit?: number): Promise<BrainSearchHit[]>;
  getPreferences(): Promise<string[]>;
  savePreference(fact: string): Promise<{ status: "saved" | "already_known" }>;
  forgetPreference(fact: string): Promise<{ status: "removed" | "not_found" }>;
  findRelated(slug: string): Promise<{ count: number; results: RelatedPage[] }>;
};

// Read on every chat request before anything streams, so it must fail fast.
const PREFERENCES_READ_TIMEOUT_MS = 8_000;

export function createBrain(
  deps: { db: Db; embedder: Pick<Embedder, "query"> },
  options: { preferencesTimeoutMs?: number } = {},
): Brain {
  async function search(source: SourceKind, query: string, limit: number): Promise<BrainSearchHit[]> {
    let queryEmbedding: number[] | null = null;
    try {
      queryEmbedding = await deps.embedder.query(query);
    } catch (err) {
      // A rate-limited or failing embedding service must not make search fail:
      // keyword search still works.
      console.error("Query embedding failed; using keyword search only", err);
    }
    return searchDocuments(deps.db, { query, queryEmbedding, source, limit });
  }

  /**
   * The chat's injection read: never throws, never hangs. Save/forget below do
   * NOT use this; they propagate database errors so a failed read can never be
   * mistaken for "no preferences" by a read-modify-write.
   */
  async function getPreferences(): Promise<string[]> {
    const timeoutMs = options.preferencesTimeoutMs ?? PREFERENCES_READ_TIMEOUT_MS;
    let timer: ReturnType<typeof setTimeout> | undefined;
    const timeout = new Promise<string[]>((resolve) => {
      timer = setTimeout(() => {
        console.error(`Preferences read took over ${timeoutMs}ms; continuing without them`);
        resolve([]);
      }, timeoutMs);
    });
    const read = listPreferences(deps.db).catch((err) => {
      console.error("Failed to read preferences; continuing without them", err);
      return [] as string[];
    });
    try {
      return await Promise.race([read, timeout]);
    } finally {
      clearTimeout(timer);
    }
  }

  return {
    searchGmail: (query, limit = 10) => search("gmail", query, limit),
    searchDrive: (query, limit = 10) => search("drive", query, limit),
    searchCalendar: (query, limit = 10) => search("calendar", query, limit),
    getPreferences,
    savePreference: (fact) => addPreference(deps.db, fact),
    forgetPreference: (fact) => removePreference(deps.db, fact),
    findRelated: (slug) => relatedTo(deps.db, slug),
  };
}
```

```ts
import { createBrain, type Brain } from "./brain.ts";
import type { Db } from "./db.ts";
import { createPostgresDb } from "./pg.ts";

let dbPromise: Promise<Db> | null = null;
let embedder: Embedder | null = null;

/**
 * One connection pool per serverless instance; the schema is created on first
 * use, so no manual SQL is ever needed. A failure is not cached, so a database
 * that was paused and then restored recovers on the next request.
 */
export function getDb(): Promise<Db> {
  if (!dbPromise) {
    dbPromise = (async () => {
      const url = process.env.DATABASE_URL;
      if (!url) throw new Error("Missing required env var DATABASE_URL");
      const db = createPostgresDb(url);
      await applySchema(db);
      return db;
    })().catch((err) => {
      dbPromise = null;
      throw err;
    });
  }
  return dbPromise;
}

export function getEmbedder(): Embedder {
  embedder ??= createEmbedder();
  return embedder;
}

export async function getBrain(): Promise<Brain> {
  return createBrain({ db: await getDb(), embedder: getEmbedder() });
}
```

```ts
 * Order matters: Supabase's pooler answers a paused project with
 * "(ENOTFOUND) tenant/user postgres.<ref> not found", which also contains
 * ENOTFOUND, so "paused" must be checked before "unreachable".
 */
export function describeDbError(err: unknown): { kind: DbProblemKind; message: string } {
  const text = (err instanceof Error ? `${err.name} ${err.message}` : String(err)).toLowerCase();
  let kind: DbProblemKind = "unknown";
  if (text.includes("missing required env var database_url")) kind = "not_configured";
  else if (/tenant\/user .* not found|tenant or user not found/.test(text)) kind = "paused";
  else if (/did not respond|timeout|timed out/.test(text)) kind = "timeout";
  else if (/enotfound|econnrefused|econnreset|connection terminated/.test(text)) kind = "unreachable";
  return { kind, message: DB_PROBLEM_MESSAGES[kind] };
}
```

```ts
/** Runs steps one at a time (so timings do not overlap), recording each failure instead of throwing. */
export async function timeSteps(
  steps: { call: string; run: () => Promise<unknown> }[],
  now: () => number = Date.now,
): Promise<StepTiming[]> {
  const timings: StepTiming[] = [];
  for (const step of steps) {
    const start = now();
    try {
      await step.run();
      timings.push({ call: step.call, ok: true, ms: now() - start });
    } catch (err) {
      timings.push({
        call: step.call,
        ok: false,
        ms: now() - start,
        error: err instanceof Error ? err.message : String(err),
      });
    }
  }
  return timings;
}
```

```ts
// Mirrors SyncProgress in src/lib/sync/engine.ts. Duplicated on purpose: that
// module pulls in server-only code (node:crypto, the database layer) that must
// not be bundled into the browser.
export type SyncProgress = {
  phase: "fetch" | "embed";
  skipped?: boolean;
  counts: { gmail: number; drive: number; calendar: number } | null;
  documents: number;
  changed: number;
  embedded: number;
  remaining: number;
};

export type FullSyncResult = {
  counts: SyncProgress["counts"];
  documents: number;
  changed: number;
  embedded: number;
  remaining: number;
  skipped: boolean;
  stalled: boolean;
};

/**
 * One fetch request, then embed requests while anything is left. The server does
 * about 40s of embedding per request (Vercel's limit is 60s), so a first full
 * sync takes a few rounds. Stops early if a round embeds nothing (e.g. the
 * embedding service is rate-limited) rather than spinning.
 */
export async function runFullSync(
  options: {
    auto?: boolean;
    fetchFn?: typeof fetch;
    onProgress?: (progress: SyncProgress) => void;
    maxRounds?: number;
  } = {},
): Promise<FullSyncResult> {
  const { auto = false, onProgress, maxRounds = 30 } = options;
  const fetchFn: typeof fetch = options.fetchFn ?? ((input, init) => fetch(input, init));

  async function call(body: object): Promise<SyncProgress> {
    const res = await fetchFn("/api/ingest/sync", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify(body),
    });
    const data = await res.json();
    if (!res.ok) throw new Error(data?.error ?? "Sync failed");
    return data as SyncProgress;
  }

  let progress = await call({ phase: "fetch", auto });
  onProgress?.(progress);

  const result: FullSyncResult = {
    counts: progress.counts,
    documents: progress.documents,
    changed: progress.changed,
    embedded: progress.embedded,
    remaining: progress.remaining,
    skipped: Boolean(progress.skipped),
    stalled: false,
  };

  for (let round = 0; round < maxRounds && result.remaining > 0; round++) {
    progress = await call({ phase: "embed" });
    onProgress?.(progress);
    result.embedded += progress.embedded;
    result.remaining = progress.remaining;
    result.documents = progress.documents;
    if (progress.embedded === 0) {
      result.stalled = result.remaining > 0;
      break;
    }
  }
  return result;
}
```

```ts
          gmail: messages.map(gmailMessageToBrainDocument),
          drive: files.map(driveFileToBrainDocument),
          calendar: events.map(calendarEventToBrainDocument),
```

```ts
  type UIMessage,

import { createToolBudget } from "@/lib/query/tool-budget";
import { getBrain } from "@/lib/store/service";

// 60s is the max Vercel's Hobby plan allows. Needed as headroom: the model
// can call search_gmail/search_drive multiple times per turn, each one a
// round-trip to the database and the embedding API.
export const maxDuration = 60;

/**
 * Most Gemini API failures (rate limits, overload) surface DURING streaming,
 * not as a synchronous throw from `streamText()` itself — it returns
 * immediately and the actual model call happens lazily as the stream is
 * consumed. That's why this is wired into `toUIMessageStreamResponse`'s
 * `onError` (which controls the error text embedded in the stream) rather
 * than only a try/catch around `streamText()`. The AI SDK retries
 * transiently-retryable errors internally a few times first and wraps the
 * final failure in a `RetryError` — unwrap `.lastError` to get at the real
 * `APICallError` and its `statusCode`.
 */
function friendlyErrorMessage(error: unknown): string {
  const resolved = RetryError.isInstance(error) ? error.lastError : error;
  const statusCode = APICallError.isInstance(resolved) ? resolved.statusCode : undefined;

  if (statusCode === 429) {
    return "[ ERR_HIGH_DEMAND ] Model is currently experiencing high demand (rate limited). Please wait a moment and try your query again.";
  }
  if (statusCode === 503 || statusCode === 500) {
    return "[ ERR_SERVICE_OVERLOAD ] The model provider is temporarily overloaded. Please retry in a moment.";
  }
  if (statusCode !== undefined) {
    return `[ ERR_UPSTREAM_${statusCode} ] The model provider returned an unexpected error. Please try again.`;
  }

  console.error("Unclassified chat error", error);
  return "[ SYSTEM_ALERT ] Something went wrong generating a response. Please try again.";
}

/** A broken or paused database must not stop the chat from replying at all: continue without preferences. */
async function loadPreferences(): Promise<string[]> {
  try {
    return await (await getBrain()).getPreferences();
  } catch (err) {
    console.error("Preferences unavailable; continuing without them", err);
    return [];
  }
}

export async function POST(req: Request) {
  try {
    const { session, error } = await requireSession();
    if (error) return error;

    const { messages }: { messages: UIMessage[] } = await req.json();

    const startedAt = Date.now();
    const preferences = await loadPreferences();
    const systemPrompt = getSystemPrompt(preferences);

    const result = streamText({
      model: google(CHAT_MODEL_ID),
      system: systemPrompt,
      messages: await convertToModelMessages(messages),
      tools: createBrainTools(session.accessToken, session.user?.email ?? ""),
      stopWhen: stepCountIs(5),
      // See tool-budget.ts: once ~28s are spent, force an answer rather than
      // let more search steps run into Vercel's 60s kill with nothing shown.
      prepareStep: createToolBudget(systemPrompt, startedAt),
    });

    return result.toUIMessageStreamResponse({ onError: friendlyErrorMessage });
  } catch (err) {
    // Genuinely synchronous failures only (bad request body, auth, our own
    // code throwing before streamText is ever invoked) — model/API errors
    // are caught above via onError instead.
    console.error("Chat request failed before streaming started", err);
    return new Response(JSON.stringify({ error: friendlyErrorMessage(err) }), {
      status: 500,
      headers: { "Content-Type": "application/json" },
    });
  }
}
```

````markdown
# Enagram.io

A conversational AI agent over your own Gmail, Google Drive and Google Calendar. Ask
questions in plain language and it searches, correlates and reasons across all three in
a single answer instead of making you search each one separately.

**Live:** https://enagram-io.vercel.app

This is **v2**. v1 ([Halok600/Enagram.io](https://github.com/Halok600/Enagram.io)) used a
separate gbrain server on Render plus a Colab notebook for ingestion; v2 keeps every
feature and replaces that stack with Supabase Postgres + pgvector queried directly from
Vercel, so there is nothing to start by hand.

## What it does

- **Cross-source Q&A** — one answer drawing on Gmail, Drive and Calendar together.
- **Calendar from chat** — create, update and delete real events conversationally, plus a
  full `/calendar` page (month/week view, drag-and-drop rescheduling) sharing the same code.
- **Gmail reply drafting** — drafts (never sends) a correctly threaded reply.
- **Preference memory** — "remember that I prefer concise answers" persists across sessions.
- **Cross-source linking** — items sharing a participant are linked so the agent can follow
  a connection instead of guessing a new search.
- **Streaming chat UI** with animated tool activity and dark/light themes.

## Architecture

```
Browser ── Vercel (Next.js 16) ──┬── Google APIs (Gmail / Drive / Calendar)
                                 ├── Gemini (chat model + embeddings)
                                 └── Supabase Postgres + pgvector
```

- **Search** is hybrid: Postgres full-text (OR-ed terms, English stemming) plus Gemini
  embeddings (768-dim, cosine), merged with Reciprocal Rank Fusion. If the embedding service
  is unavailable, keyword search still works.
- **Sync** runs inside the site in two idempotent phases: fetch and store text, then embed in
  time-boxed chunks. Unchanged documents are never re-embedded.
- **Storage** tables (`enagram_*`) are created automatically on first use.
- Design and plan: `docs/superpowers/specs/` and `docs/superpowers/plans/`.
````
